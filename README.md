# Учебное приложение для практической работы №13

Локальный стенд для аудита формы входа: одна форма в двух версиях, **уязвимой** (`/vulnerable`) и **исправленной** (`/secure`). Проект создан для практической работы №13 курса «Информационная безопасность» на Stepik. Он демонстрирует атаку и повторную проверку после исправления. Запускайте сервер только на своей машине: он привязан к `127.0.0.1:8008`.

## Запуск

Требуется Python 3.10+; сторонние пакеты не нужны.

```bash
python3 auth_lab.py
```

Откройте `http://127.0.0.1:8008/vulnerable` и `http://127.0.0.1:8008/secure`. Тестовый пользователь: `alice`, пароль: `correct-horse`. Оба значения относятся только к базе в памяти и не используются вне стенда.

## Архитектура

HTML-форма отправляет `username` и `password` методом POST. `Handler` передаёт их в `VulnerableAuth` или `SecureAuth`; каждая версия использует собственную SQLite-базу в памяти. Функция `login` возвращает результат, который выводится в HTML. Данные исчезают при остановке процесса.

| Уязвимость | Маркер в коде | Исправление |
|---|---|---|
| SQL-инъекция через конкатенацию запроса | V1 | Параметризованный запрос S1 |
| Пароль в открытом виде | V2 | Соль и `hashlib.scrypt` S2 |
| Нет проверки ввода | V3 | Ограничения длины и символов S3 |
| Нет ограничения попыток | V4 | Блокировка на 60 секунд после 5 ошибок S4 |
| Раскрытие существования пользователя | V5 | Одинаковый ответ об ошибке S2 |

`scrypt` — функция выработки ключа с затратами памяти; в задании в качестве примеров указаны bcrypt и Argon2. Здесь выбран вариант из стандартной библиотеки Python, чтобы стенд запускался без установки зависимостей.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Ключевой сценарий: логин `' OR 1=1 --` с неверным паролем `x` проходит в `/vulnerable`, но отклоняется в `/secure`. Тесты также проверяют хранение пароля, валидацию ввода, различие ошибок и ограничение перебора.

## Границы стенда

Версия `/vulnerable` **намеренно небезопасна**. Не размещайте приложение в открытой сети и не вводите реальные учётные данные. Исправленная версия показывает ровно пять исправлений из учебного задания; это не готовый сервис для промышленного использования: в нём нет полноценной сессии, HTTPS, журналирования и общего для нескольких процессов лимита попыток.
